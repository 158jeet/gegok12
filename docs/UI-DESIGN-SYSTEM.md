# Tagore ERP UI Design System

## Single source of truth

- Authoritative stylesheet: `resources/assets/css/tagore-erp.css`.
- Published stylesheet: `public/tagore-erp.css`, generated by Laravel Mix from the authoritative stylesheet (`webpack.mix.js`).
- Application shells load the published stylesheet with a file modification cache-buster: `layouts/app`, `layouts/main`, `layouts/minimal`, and `layouts/admission`.
- Standalone Tagore application pages must link to the same published stylesheet. Print/PDF/email/payment documents retain their document-specific presentation where the application workspace theme is inappropriate.

## Change policy

1. Change design tokens and shared component rules in the authoritative stylesheet, not in individual Blade templates.
2. Use semantic component classes and CSS variables for cards, tables, forms, status badges, navigation, spacing, and responsive behavior.
3. Keep page-specific layout rules in a separate page stylesheet when necessary; do not embed global design-system rules in Blade `<style>` blocks or inline `style` attributes.
4. Scope the dark workspace theme to `body.tg-app` so it does not unexpectedly restyle printable receipts, PDF reports, payslips, or transactional email.
5. Rebuild assets using `npm run build` so `public/tagore-erp.css` stays synchronized with `resources/assets/css/tagore-erp.css`.
6. After a design change, run Blade rendering and browser acceptance checks at desktop and mobile sizes, including overflow, form controls, tables, contrast, console errors, and key workflow actions.

## Release checks

- Verify all application shells and standalone application pages reference `public/tagore-erp.css`.
- Verify `resources/assets/css/tagore-erp.css` contains the canonical changes before any build.
- Compare desktop and mobile screenshots across all eight access levels before release.
- Keep generated CSS/JS changes and UI source changes together in the same reviewed release.
